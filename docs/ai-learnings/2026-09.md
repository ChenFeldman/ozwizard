# AI learnings — 2026-09

## The transitive-denylist bypass was locked in by its own test — 2026-09-12

**Context:** OZ-105, a customer report that a denylisted package passed Acme's scan. Root
cause was the known `dep.direct &&` guard on the denylist filter in `evaluate`
(`src/core/policy.ts:75`), which dropped transitively-resolved denylisted deps — with no
advisory of their own they produced _no findings at all_, so the verdict was `allow`.
**What we learned:** The suite stayed green not because the case was uncovered but because
`test/policy.test.ts` had a test named `does not block denylisted transitive dependency`
asserting `verdict === 'allow'`. A test can encode the defect as expected behavior; a green
suite is evidence about the assertions, not about the requirement. The requirement lives in
`.claude/rules/core.md` ("Transitive deps are first-class") and
`docs/llm-wiki/policy-verdicts.md`, both of which contradicted that test.
**How to apply next time:** When a bug report conflicts with a passing test, read the test
before the code — if it asserts the buggy behavior, inverting it _is_ the regression test
(say so out loud; don't quietly relax assertions). Cross-check the intended semantics
against `.claude/rules/core.md` and `docs/llm-wiki/` rather than against the suite.
